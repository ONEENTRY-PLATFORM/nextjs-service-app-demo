### 🔴 high · Доступность (a11y) · Кликабельные карточки-div без клавиатурного доступа блокируют шаг «Specialist» в бронировании

**Файлы:** `components/layout/booking-page/components/MasterCard.tsx:51`, `components/layout/booking-page/components/MasterCard.tsx:123`, `components/layout/booking-page/components/AnySpecialistCard.tsx:47`, `components/layout/booking-page/components/AnySpecialistCard.tsx:95`, `components/layout/home/offers-feed/components/OfferCard.tsx:90`

Тот же паттерн у OfferCard на главной: <div onClick={() => router.push('/offers')}> (внутренняя кнопка Book доступна, но навигация по карточке — нет). **Рекомендация:** Переделать карточки на <button type="button"> (у них уже text-left и нет вложенного интерактива, кроме OfferCard) либо повторить паттерн GalleryGridCell: role="button", tabIndex={0}, обработка Enter/Space, aria-pressed={active} для состояния выбора. ### 🔴 high · Доступность (a11y) · Брендовые цвета текста массово не проходят WCAG-контраст: #a8a9b5 — 2.33:1, #ed21f1 — 3.45:1

**Файлы:** `app/globals.css:50`, `app/globals.css:31`, `components/layout/booking-page/components/MasterCard.tsx:99`, `components/layout/home/offers-feed/components/OfferCard.tsx:17`, `components/layout/home/reviews-carousel/components/ReviewsCarousel.tsx:162`

По WCAG-формуле: MUTED #a8a9b5 (токен --color-neutral-300) на белом даёт 2.33:1 — ниже даже порога 3:1 для крупного текста, а класс text-neutral-300 используется 105 раз как основной цвет описаний, подсказок, empty-state и биографий мастеров (16px). PINK #ed21f1 (text-accent-pink/text-fuchsia-500, 75 использований) на белом — 3.45:1: проходит только как крупный текст, но применяется к мелким ссылкам и меткам (например, «View all reviews» 16px, цены, специализации в карточках). Белый текст на градиентных кнопках bg-gradient-brand в «розовой» части — 3.29–3.45:1 при мелком uppercase-шрифте. axe-тест это не ловит: color-contrast имеет impact=serious, а тест роняет только critical.

**Рекомендация:** Согласовать с дизайном затемнённые «доступные» варианты токенов: для вторичного текста заменить #a8a9b5 на цвет с контрастом ≥4.5:1 (например, #6f7180); розовый текст мелкого кегля — темнее (например, #c012c4 даёт ≥4.5:1) либо увеличивать кегль/вес до large text. Ввести отдельные токены --color-text-muted/--color-text-accent, не трогая декоративные заливки.

### 🔴 high · Устойчивость и обработка ошибок · Транзиентный сбой CMS запекает 404 в ISR на payment-страницах, салонах и мастерах

**Файлы:** `app/[handle]/page.tsx:46`, `app/salons/[handle]/page.tsx:39`, `app/masters/[handle]/page.tsx:54`

Проект уже создал resolveCmsPage именно для того, чтобы отличать 'страницы нет' (стабильный 404 из CMS) от 'CMS недоступна' (транзиентный сбой), и внедрил его в app/services/[handle] и app/gallery/[handle]. Но три роута остались на старом паттерне: app/[handle]/page.tsx:46 делает `if (isError || !page) return notFound()` — это роут payment_success/payment_canceled, куда пользователь возвращается из Stripe сразу после оплаты; при транзиентном таймауте/5xx он увидит 404, и с revalidate=60 этот 404 закэшируется на всё окно. app/salons/[handle]/page.tsx:39 — тот же паттерн на force-static + revalidate 300. app/masters/[handle]/page.tsx:54-58 игнорирует isError из getMastersList(): при сбое admins === undefined → `admins?.find(...)` → notFound() для ЛЮБОГО мастера (revalidate 60). unstable_cache сбой не кэширует (fetchCmsData бросает), но page-level ISR-кэш запекает сам 404-рендер.

**Рекомендация:** Перевести все три роута на resolveCmsPage (или эквивалентную проверку `error?.statusCode === 404`): notFound() — только на подтверждённый 404; при 'unavailable' на payment-страницах показать нейтральный фолбэк-экран статуса оплаты, на salons/masters — деградировать или бросить, чтобы ISR сохранил прошлую валидную версию страницы.

### 🔴 high · Тесты и DX · Lock-файл не коммитится при ^-диапазонах всех зависимостей

**Файлы:** `.gitignore:44`, `package.json:25-81`, `README.md:83-93`

package-lock.json явно занесён в .gitignore (строка 44) и отсутствует в git (git ls-files не находит ни одного lock-файла), при этом все 50+ зависимостей заданы caret-диапазонами (next ^16.2.10, react ^19.2.7, oneentry ^1.0.156, gsap ^3.15.0 и т.д.). **Рекомендация:** Убрать package-lock.json из .gitignore и закоммитить его; в деплой-пайплайне (GitLab-репо) и будущем CI использовать npm ci вместо npm install. Опционально — pin точных версий критичных пакетов (next, oneentry).

#### 🟠 medium · Утилита dictText почти не используется — 300+ инлайновых чтений словаря с латентным отказом фолбэка

**Файлы:** `components/utils/dictText.ts:15`, `components/layout/masters-page/components/SalonFilter.tsx:65`, `components/layout/mobile-menu/components/CloseModal.tsx:21`, `components/layout/contacts-page/ContactFormCard.tsx`, `components/utils/buildSocialLinks.ts`, `components/layout/contacts-page/utils/buildContactRows.ts`

Существует утилита dictText, которая принимает значение словаря только если это непустая строка (её JSDoc прямо документирует: незаполненный атрибут CMS приходит как пустой массив). Но она используется лишь в 2 файлах (7 вызовов), тогда как паттерн '(dict?.marker?.value as string | undefined) || "Fallback"' скопирован 308 раз в 117 файлах (283 в components/, 25 в app/). Инлайновый каст не защищает от нестрокового значения: пустой массив truthy, '[] || fallback' вернёт массив — фолбэк не сработает, и текст просто исчезнет из UI при незаполненном маркере. То есть массовая копипаста ещё и семантически слабее той утилиты, которая была написана именно для этого случая.

**Рекомендация:** Прогнать кодмод по всем вызовам: заменить инлайновый паттерн на dictText(dict, 'marker', 'Fallback') (или добавить в useDict обёртку-геттер с той же семантикой). Это одна механическая замена, устраняющая и дублирование, и латентный баг с пустыми массивами.

#### 🟠 medium · Миграция на createCachedCmsReader остановилась на полпути — 10 обёрток всё ещё дублируют три слоя вручную

**Файлы:** `app/api/utils/createCachedCmsReader.ts:30`, `app/api/server/admins/getAdminsInfo.tsx:25`, `app/api/server/blocks/getBlockSlides.ts:18`, `app/api/server/blocks/getBlocks.ts:20`, `app/api/server/blocks/getBlocksByPageUrl.ts:28`, `app/api/server/attributes/getSingleAttributeByMarkerSet.ts:21`, `app/api/server/pages/getChildPagesByParentUrl.ts:18`, `app/api/server/pages/getPagesByIds.ts:19`, `app/api/server/products/getProducts.ts:23`, `app/api/server/products/getProductsByPageUrl.ts:45`, `app/api/server/products/getRelatedProductsById.ts:18`
